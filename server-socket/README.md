# Road Help — WebSocket-сервер (лабораторная работа №7)

Сервер реального времени на Express + Socket.IO для чата поддержки по заявкам и уведомлений.
Работает независимо от REST API: REST-серверы проекта — на портах 3000 (PostgreSQL) и 3001 (MongoDB),
этот сервер занимает порт **3002**, а историю сообщений хранит в MongoDB.

## Что реализовано

- подключение клиента по Socket.IO и уведомление о входе/выходе в чат;
- комнаты по заявкам: чат каждой заявки изолирован (`request:<id>`);
- отправка и получение сообщений в реальном времени, подтверждение получения (acknowledgement);
- событие «печатает» (typing) без отправки самого сообщения;
- история сообщений в MongoDB (коллекция `messages`), последние 50 при входе в комнату;
- системные сообщения о входе, выходе и смене статуса заявки;
- уведомление о новой заявке всем подключённым клиентам;
- ограничение длины сообщения (1000 символов) и частоты (не более 20 сообщений за 10 секунд).

## Структура

```
server-socket/
├── server.js            Express + Socket.IO, обработчики событий, REST-уведомления
├── models/Message.js    схема сообщения в MongoDB
├── test-chat.js         сценарий проверки чата двумя клиентами

├── .env                 MONGO_URI, PORT, CLIENT_ORIGIN (в git не попадает)

```

## Запуск

**1. MongoDB** (локальная установка из лабораторной №6):

```bash
~/mongodb-install/start-mongo.sh
```

**2. Сервер реального времени:**

```bash
cd server-socket
npm install
npm run dev
```

В выводе должно появиться `MongoDB connected` и `Realtime server running on port 3002`.
Проверка: `http://localhost:3002/health` возвращает `{"status":"ok","connections":N}`.

**3. Клиент:** React-приложение из лабораторной №5 (`client`), в нём на каждой карточке заявки есть кнопка «Чат».
Клиент подключается по адресу из переменной `VITE_SOCKET_URL` (файл `client/.env`, по умолчанию `http://localhost:3002`).

## События Socket.IO

| Направление | Событие | Данные | Назначение |
|---|---|---|---|
| клиент → сервер | `join` | `{ requestId, user }` | вход в комнату заявки |
| клиент → сервер | `message` | `{ requestId, user, text }` | отправка сообщения (есть ack) |
| клиент → сервер | `typing` | `{ requestId, user, isTyping }` | индикатор набора текста |
| клиент → сервер | `leave` | — | выход из комнаты |
| сервер → клиент | `connected` | `{ socketId }` | подтверждение подключения |
| сервер → клиент | `history` | `{ requestId, messages }` | история при входе в комнату |
| сервер → клиент | `message` | объект сообщения | новое сообщение в комнате |
| сервер → клиент | `typing` | `{ user, isTyping }` | кто-то печатает |
| сервер → клиент | `status-changed` | `{ requestId, status, changedBy }` | статус заявки изменён |
| сервер → клиент | `request-created` | `{ requestId, description }` | создана новая заявка |
| сервер → клиент | `presence` | `{ user, status }` | участник отключился |
| сервер → клиент | `error-message` | `{ error }` | ошибка обработки события |

## REST-маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | /health | состояние сервера и число подключений |
| GET | /api/messages/:requestId | история сообщений заявки (до 50 последних) |
| POST | /api/notify/status | уведомить комнату о смене статуса заявки |
| POST | /api/notify/request | уведомить всех о новой заявке |

## Проверка

Автоматический сценарий двумя клиентами:

```bash
node test-chat.js
```

Проверяются: подключение двух клиентов, получение истории, уведомление о входе, событие «печатает»,
подтверждение получения, доставка сообщения, изоляция комнат и уведомление об отключении.

Ручная проверка: открыть приложение в двух окнах браузера, войти под разными аккаунтами, открыть
чат по одной и той же заявке и обменяться сообщениями — сообщения и системные уведомления появляются
в обоих окнах без перезагрузки страницы.
