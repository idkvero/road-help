# API сервиса помощи на дорогах

REST API для управления заявками на помощь водителям. Данные хранятся в памяти приложения.

Базовый адрес: `http://localhost:3006`

Формат данных: JSON (`Content-Type: application/json`).

## Ресурсы

| Ресурс | URL | Назначение |
|---|---|---|
| Пользователи | `/users` | водители, создающие заявки |
| Диспетчеры | `/operators` | сотрудники, обрабатывающие заявки |
| Заявки | `/requests` | обращения водителей |

## Коды состояния

| Код | Значение |
|---|---|
| 200 OK | запрос выполнен |
| 201 Created | ресурс создан |
| 204 No Content | ресурс удалён, тело ответа отсутствует |
| 400 Bad Request | ошибка валидации входных данных |
| 404 Not Found | ресурс не найден |
| 409 Conflict | конфликт (повтор email, удаление связанного ресурса) |
| 500 Internal Server Error | внутренняя ошибка сервера |

Формат ошибки:

```json
{
  "error": "Ошибка валидации данных",
  "details": ["Поле description обязательно"]
}
```

## Пользователи

### GET /users

Список пользователей с поиском и пагинацией.

Параметры строки запроса:

| Параметр | Описание |
|---|---|
| `search` | поиск по имени или email |
| `page` | номер страницы (по умолчанию 1) |
| `limit` | размер страницы (по умолчанию 10, максимум 50) |

Пример: `GET /users?search=иван&page=1&limit=10`

Ответ `200 OK`:

```json
{
  "total": 1,
  "page": 1,
  "limit": 10,
  "items": [
    { "id": 1, "name": "Иван Петров", "email": "ivan@mail.com", "phone": "+375291112233" }
  ]
}
```

### GET /users/:id

Детали пользователя.

Ответ `200 OK`:

```json
{ "id": 1, "name": "Иван Петров", "email": "ivan@mail.com", "phone": "+375291112233" }
```

Ошибки: `404 Not Found` — `{ "error": "Пользователь не найден" }`.

### POST /users

Создание пользователя.

Тело запроса:

```json
{
  "name": "Иван Петров",
  "email": "ivan@mail.com",
  "phone": "+375291112233"
}
```

Ответ `201 Created` — созданный пользователь с присвоенным `id`.

Ошибки: `400` (не указано имя, некорректный email или телефон), `409` (email уже занят).

### PUT /users/:id

Полное обновление пользователя: обязательны `name` и `email`.

Ответ `200 OK` — обновлённый пользователь.

Ошибки: `400`, `404`, `409`.

### PATCH /users/:id

Частичное обновление: передаются только изменяемые поля.

Пример:

```json
{ "phone": "+375299998877" }
```

Ответ `200 OK` — обновлённый пользователь.

### DELETE /users/:id

Удаление пользователя.

Ответ `204 No Content` без тела.

Ошибки: `404` — пользователь не найден, `409` — у пользователя есть заявки.

### GET /users/:id/requests

Заявки пользователя (связь между ресурсами).

Ответ `200 OK`:

```json
{ "total": 2, "items": [ { "id": 1, "description": "…", "status": "new" } ] }
```

## Диспетчеры

Ресурс устроен так же, как пользователи; дополнительно есть поле `shift` (`day` или `night`).

| Метод | URL | Описание | Ответ |
|---|---|---|---|
| GET | `/operators` | список, фильтр по `shift` | 200 |
| GET | `/operators/:id` | детали | 200, 404 |
| POST | `/operators` | создание | 201, 400, 409 |
| PUT | `/operators/:id` | полное обновление | 200, 400, 404, 409 |
| PATCH | `/operators/:id` | частичное обновление | 200, 400, 404, 409 |
| DELETE | `/operators/:id` | удаление | 204, 404, 409 |
| GET | `/operators/:id/requests` | заявки диспетчера | 200, 404 |

Тело запроса для создания:

```json
{
  "name": "Дмитрий Ковалёв",
  "email": "kovalev@roadhelp.by",
  "phone": "+375294445566",
  "shift": "day"
}
```

## Заявки

### GET /requests

Список заявок с фильтрацией, поиском и пагинацией.

Параметры:

| Параметр | Описание |
|---|---|
| `status` | `new`, `in_progress`, `completed` |
| `userId` | заявки конкретного пользователя |
| `operatorId` | заявки конкретного диспетчера |
| `search` | поиск по описанию |
| `page`, `limit` | пагинация |

Пример: `GET /requests?status=new&page=1&limit=10`

Ответ `200 OK`:

```json
{
  "total": 4,
  "page": 1,
  "limit": 10,
  "items": [
    {
      "id": 1,
      "description": "Не заводится автомобиль после ночной стоянки",
      "location": "Минск, ул. Сурганова, 15",
      "status": "new",
      "userId": 1,
      "operatorId": 1,
      "createdAt": "2026-11-14T09:15:00.000Z",
      "user": { "id": 1, "name": "Иван Петров", "email": "ivan@mail.com" },
      "operator": { "id": 1, "name": "Дмитрий Ковалёв", "shift": "day" }
    }
  ]
}
```

### GET /requests/:id

Детали заявки. Ответ `200 OK` — объект заявки с вложенными данными пользователя и диспетчера.

Ошибки: `404 Not Found`.

### POST /requests

Создание заявки.

Тело запроса:

```json
{
  "description": "Спустило колесо на МКАД",
  "location": "Минск, МКАД, 25-й км",
  "status": "new",
  "userId": 2,
  "operatorId": 1
}
```

Обязательные поля: `description`, `location`, `userId`. Поле `status` по умолчанию `new`, `operatorId` можно не указывать.

Ответ `201 Created` — созданная заявка.

Ошибки: `400` (нет обязательного поля, неверный статус, несуществующий `userId` или `operatorId`).

### PUT /requests/:id

Полное обновление: обязательны `description`, `location`, `status`, `userId`.

Ответ `200 OK`.

Ошибки: `400`, `404`.

### PATCH /requests/:id

Частичное обновление: передаются только изменяемые поля.

Пример:

```json
{ "location": "Минск, МКАД, 26-й км" }
```

Ответ `200 OK`.

Ошибки: `400`, `404`.

### PATCH /requests/:id/status

Изменение статуса заявки (дополнительная операция).

```json
{ "status": "in_progress" }
```

Ответ `200 OK` — заявка с новым статусом.

Ошибки: `400` (недопустимый статус), `404`.

### PATCH /requests/:id/operator

Назначение диспетчера на заявку. Передача `null` снимает назначение.

```json
{ "operatorId": 2 }
```

Ответ `200 OK`.

Ошибки: `400` (диспетчер не найден), `404`.

### DELETE /requests/:id

Удаление заявки.

Ответ `204 No Content`.

Ошибки: `404 Not Found`.

## Идемпотентность

`GET`, `PUT`, `PATCH` и `DELETE` в этом API идемпотентны: повторный запрос с теми же данными приводит к тому же состоянию ресурса, что и первый. `POST` не идемпотентен — повторный вызов создаёт новую запись.
